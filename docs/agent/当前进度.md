## 2. 已完成的功能

### 2.1 核心运行时与流水线编排（Protocol v2）
- [x] **v2 统一资源规范**：InputResource / OutputResource / PluginContract；ResourceType 支持 string, number, boolean, json, file, directory, list。
- [x] **v1 插件自动升级**：`_upgrade_v1_to_v2` 兼容平滑转换。
- [x] **插件安全接入**：Git, HTTP ZIP, 本地上传, ToolHub 集成；路径穿越与超限安全校验。
- [x] **DAG 拓扑编排**：依赖检测、环检测、并发就绪判定。
- [x] **三类接线表达式**：`${{ params.* }}`、`${{ steps.<dep>.outputs.* }}`、`${{ all.deps.outputs.* }}`。
- [x] **隔离工作区规范**：`workspace/{input,output,temp,cache,logs}` + `context.json` + `params.json`。
- [x] **健壮调度器**：双线程池（`coordinator_workers` + `task_workers`）、进程树级终止（Windows taskkill / POSIX killpg）、步骤重试与指数退避。

### 2.2 多用户系统与安全授权
- [x] **用户账户体系**：用户注册、登录、密码 `scrypt` 加盐哈希；首个注册用户自动 Bootstrap 成为平台超级管理员。
- [x] **Token 会话与鉴权中间件**：`mpt_...` 用户令牌会话持久化与校验；`/api/auth/mode` 动态暴露登录配置；全局路由拦截保护。
- [x] **资源归属与共享**：流水线、插件、机器属主（`owner_id`），`share_grants` 授权体系（viewer / operator）。
- [x] **机密存储**：基于 Fernet 对称加密静态加密机器凭据（`security.secret_key`）。
- [x] **审计日志**：用户关键操作（注册、流水线提交、机器修改、权限授权）落 `audit_logs` 审计表。

### 2.3 多机器与分布式远程执行
- [x] **机器分类管理**：
  - **个人机（Personal）**：用户自主接入，全权管理，可授权给同伴；
  - **管理员机（Admin Pool）**：平台统一纳管，可下发给用户使用但对普通用户屏蔽底层机密凭证。
- [x] **Pull 模式 Runner Agent**：
  - 基于出站 HTTP 长轮询原子认领任务（Postgres `SKIP LOCKED` 语义）；
  - 任务包（Bundle）打包分发与自动解压；
  - 租约与心跳机制：心跳自动续期租约、拉取取消信号；
  - 孤儿租约收割器（`LeaseReaper`）：超时心跳未至自动标记任务 FAILED。
- [x] **SSH 直连推送模式**：
  - 免装 Agent，服务端通过 Paramiko 建立 SSH 与 SFTP 通道；
  - 任务包远端传输、远端启动进程、实时流式抽水回传与产物打包同步；
  - 连通性测试接口（实时握手反馈时延与异常排查）。
- [x] **单指令自适应部署（`/install`）**：
  - 类似 OpenClaw 风格的一键安装端点；
  - 基于请求客户端 `User-Agent` 自动匹配返回 Windows PowerShell 或 Linux/macOS Shell 脚本；
  - 脚本兼容 Windows PowerShell 5.1/7+ 与 Bash；
  - 支持通过 `?token=mrt_...` 参数直传，安装完成自启动 Runner Agent；
  - 前端弹窗提供多平台 Tabs 切换与管理员特权运行指导。

### 2.4 可观测性、存储与前端控制台
- [x] **实时流推送**：SSE 事件流（`/api/runs/{id}/events`）与实时日志流（`/api/runs/{id}/tasks/{step}/log/stream`）。
- [x] **数据保留策略与 GC**：`mini-pipeline-gc` 定时清理过期工作区、日志与产物。
- [x] **前端交互控制台**：React 19 + AntD 5 全功能页面（Dashboard、机器管理、流水线编排与可视化、插件详情、商店审批流、任务历史与日志流查看器）。

## 5. 已知问题与技术债

1. **Windows 文件执行位丢失**：
   - Windows 文件系统天然不支持 POSIX 权限位（`chmod +x`），断言 mode/exec bit 的测试需跳过（`test_folder_upload.py` 已做 `sys.platform == "win32"` 规避）。
2. **SQLite 单文件锁争用限制**：
   - 开发环境 SQLite 在多线程并发高频写任务（如高频日志或大量 Runner 并发心跳）时偶有 `database is locked` 风险，生产环境必须使用 PostgreSQL。
3. **任务 Bundle 驻留内存生命周期**：
   - 远程 Runner 任务打包所需的输入数据（`remote_inputs`）缓存在 API 服务内存中，一旦 API 进程重启，进行中的远程任务在重新拉包时会抛出过期失效（由启动孤儿收割机制兜底）。
