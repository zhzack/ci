### 2.3 多机器与分布式远程执行网络
- `已完成` **机器分类管理体系**：
  - **个人机（Personal）**：用户自助接入，全权管理、共享与转移；
  - **管理员机（Admin Pool）**：平台统一持有并下发分配给用户，普通使用者可跑任务但严禁读取底层凭证明文。
- `已完成` **Pull 模式 Runner Agent**：
  - 基于出站 HTTP 长轮询原子认领任务（Postgres `SKIP LOCKED` 语义）；
  - 任务包（Bundle）打包分发与自动解压；
  - 租约心跳机制：15s 心跳续租与取消信号下发；
  - 孤儿租约收割器（`LeaseReaper`）：超时心跳未至自动标记任务 FAILED。
- `已完成` **SSH 直连推送模式**：
  - 免装 Agent，服务端通过 Paramiko 建立 SSH 与 SFTP 客户端通道；
  - 远程任务包打包下发、远程执行启动、日志回传与产物打包同步；
  - 连通性测试接口（`/api/machines/{id}/test-connection`）与前端即时时延探测按钮。
- `已完成` **单指令自适应部署（`/install`）**：
  - 类似 OpenClaw 风格的跨平台单行安装端点；
  - 基于请求客户端 `User-Agent` 自动分发适配 Windows PowerShell 或 Linux/macOS Shell 的脚本；
  - 彻底修复 Windows PowerShell 5.1/7+ 兼容性；
  - 支持通过 `?token=mrt_...` 参数直传并在解压后自动后台拉起 Agent；
  - 前端弹窗提供多平台 Tabs 切换与管理员特权运行指导。
- `已完成` **Windows 执行环境全面加固**：
  - `ProcessRunner` 运行时主动将当前 Python 虚拟环境目录前置至 `PATH`，并在环境中补全 `python3.exe`，彻底绝缘 Windows 应用商店 Python 伪存根干扰（退出码 9009 / Bash 49）；
  - `mini_pipeline.runtime.shell` 优先探测并调用 Git Bash，屏蔽 System32 下未初始化的 WSL 空壳存根（退出码 127）；
  - 修复示例插件 `run.sh` 中 Quoted Heredoc 导致工作区变量未展开、触发 Windows 路径冒号非法字符（`WinError 123`）的缺陷；
  - 修复 `LogTee` 日志流在瞬态任务退出时的清空刷新（flush drain）断流缺陷，避免日志丢失。

## 5. 当前已知问题与技术债务

1. **Windows 文件系统无法保留 POSIX 执行位**：
   - 现状：Windows 上运行 `chmod +x` 无效，测试用例 `tests/unit/test_folder_upload.py` 对 mode/exec bit 的断言在 Windows 下会自动 skipif 跳过。
   - 解决方案：已符合项目测试规范，长期通过容器化运行时彻底规避。
2. **SQLite 单文件写锁并发限制**：
   - 现状：开发环境 SQLite 在高并发心跳或任务密集提交时存在锁争用风险。
   - 解决方案：生产环境强制使用 PostgreSQL 14+（通过 Docker Compose 部署）。
3. **远程任务包在 API 服务内存驻留生命周期**：
   - 现状：远程任务 bundle 数据暂存于服务端内存 `engine.remote_inputs`，若 API 服务在任务领取的瞬间重启，会导致拉包 404（由启动孤儿收割机制判定为 FAILED）。
   - 解决方案：Phase 2 接入 S3/MinIO 对象存储后将由对象持久化接管。
