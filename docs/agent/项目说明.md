# Mini Pipeline 项目说明

## 1. 项目目的

`Mini Pipeline` 是一个基于 **FastAPI + React** 开发的轻量级、企业级流水线编排与执行平台。其核心愿景是提供一种低心智负担、无技术栈绑定的 CI/CD / 任务编排引擎。

项目贯彻的核心理念是 **Pipeline Runtime Protocol v2**：
- **插件即普通进程（Zero SDK）**：插件无需集成任何特定语言的 SDK，只要是一个可执行程序（Shell 脚本、Python、Node.js 二进制可执行文件等）即可运行。
- **契约与环境解耦**：平台负责资源输入解析、工作空间初始化、环境变量注入、依赖有向无环图（DAG）调度、产物规范收集与清洗。
- **声明式接线**：流水线通过标准 YAML 语法描述 DAG 依赖拓扑，任务之间通过严格的三类表达式（`${{ params.* }}`、`${{ steps.<dep>.outputs.* }}`、`${{ all.deps.outputs.* }}`）完成数据传递。
- **多平台与多执行模式**：支持本地内置执行、基于 Pull 模型的跨平台 Runner Agent 分布式调度，以及免安装 Agent 的 SSH 直连调度。

## 2. 主要功能

1. **插件生命周期管理**：
   - 支持多种来源安全获取插件：Git 仓库拉取、HTTP 归档下载、本地 ZIP 安全上传，以及从内部 ToolHub 工具市场注册；
   - 严格的安全解压机制（路径穿越防护、软链接限制、解压容量与文件数量熔断）；
   - 插件 Manifest（`plugin.yaml`）自动化校验与 v1 格式平滑升级为 v2 契约规范。
2. **流水线编排与 DAG 解析**：
   - 声明式 Pipeline YAML 定义，自动检测依赖关系、拓扑排序与环状依赖死锁拦截；
   - 参数动态验证、默认值合并以及运行时前置检查（Preflight check）。
3. **高可靠任务调度引擎**：
   - 双线程池架构：独立协调器（Coordinator Workers）推进 DAG 与执行器（Task Workers）分配；
   - 跨平台进程树级生命周期控制（POSIX `killpg` / Windows `taskkill /T`），支持运行彻底取消；
   - 步骤级自动重试机制（指数退避与上限控制）；
   - 服务重启时自动收割孤儿任务（Reap Orphans），断点续跑支持分支运行（Branch Run）。
4. **多机器与远程执行网络**：
   - **本机内置执行**：无指定机器时走本地双线程池；
   - **分布式 Runner Agent（Pull 模式）**：长轮询认领任务、租约心跳续期机制，自适应穿越 NAT 与复杂企业内网；
   - **SSH 直连模式（Push 模式）**：服务端直连远程服务器，通过 SFTP 打包分发任务与回传产物，无缝支持已有服务器纳管；
   - **一键跨平台安装**：提供类似 OpenClaw 的单指令部署（`/install`），自动按客户端系统（PowerShell / curl）分发适配脚本，Token 直传自动拉起 Agent。
5. **用户认证与多租户权限体系**：
   - 用户注册、登录与会话管理，基于 `mpt_...` 令牌的鉴权与 RBAC（admin / user）；
   - 资源层级归属（机器、流水线、插件、运行记录均具备 owner 属性）；
   - 细粒度授权共享（`share_grants` 支持 user 级别的 viewer / operator 权限）；
   - 敏感机器凭证采用对称加密（Fernet）静态加密存储，被授权用户可跑任务但严禁读取明文凭证。
6. **插件市场与审批流**：
   - 个人插件提交上架申请（pending）；
   - 平台超级管理员审核通过（approved）后公开至市场，未经批准仅私有可见。
7. **可观测性与实时交互**：
   - 基于 Server-Sent Events（SSE）的实时流水线事件流与任务日志追加流；
   - Prometheus 文本格式指标暴露（`/metrics`）；
   - 产物下载不暴露文件系统物理路径，采用不透明 `artifact_id` 并支持 SHA256 ETag / 304 条件缓存；
   - 历史数据自动回收工具（`mini-pipeline-gc`）。
8. **现代化 Web 控制台**：
   - 基于 React 19 + Ant Design 5 + TanStack Query 搭建；
   - 具备暗色/亮色主题、响应式控制台、可视化节点连线、实时日志查看器、机器状态仪表盘等。

## 3. 技术栈

### 后端技术栈
- **语言**：Python 3.9+（测试基准为 Python 3.12）
- **Web 框架**：FastAPI 0.115+、Starlette
- **ASGI 服务器**：Uvicorn 0.30+
- **ORM 与数据库**：SQLAlchemy 2.0+、Alembic（数据库迁移）
- **数据校验与序列化**：Pydantic v2（2.8+）、pydantic-settings
- **数据库驱动**：SQLite（开发与单机）、Psycopg 3（生产 PostgreSQL）
- **安全与加密**：cryptography（Fernet 对称加密）、标准库 `hashlib.scrypt`（密码哈希）
- **远程通信**：Paramiko 3.4+（SSH/SFTP 执行器）、httpx 0.27+（HTTP 客户端）
- **可观测性**：prometheus-client 0.20+
- **测试与代码质量**：pytest 8.3+、pytest-cov、ruff 0.6+

### 前端技术栈
- **核心框架**：React 19.0、React DOM 19.0
- **开发构建工具**：Vite 5.4+、TypeScript 5.6+（严格模式，禁用 explicit any）
- **组件库与样式**：Ant Design 5.21+、@ant-design/icons
- **状态与缓存**：TanStack React Query 5.59+（服务端状态）、Zustand 5.0+（客户端状态）
- **路由**：React Router 7.0+
- **网络请求**：Axios 1.7+
- **解析与格式化**：js-yaml 4.1+
- **代码规范**：ESLint 9+、TypeScript-ESLint

## 4. 运行方式

### 4.1 环境准备
要求安装 Python 3.9+、Git（Windows 需包含 Git Bash）以及 Node.js 18+。

```bash
# 1. 创建并激活 Python 虚拟环境
python3 -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1

# 2. 安装后端依赖（含开发与测试工具）
pip install -e '.[dev]'

# 3. 前端依赖安装
cd frontend
npm install --legacy-peer-deps
cd ..
```

### 4.2 配置文件规范
配置文件严格解析环境变量，任何写在 YAML 中的 `${VAR}` 如果在操作系统未设置，启动时将直接拒绝。

开发默认配置文件位于 `config/default.yaml`。

### 4.3 启动服务

```bash
# 环境变量配置（启动服务与运行测试必须指定）
$env:MINI_PIPELINE_CONFIG="config/default.yaml"   # Windows PowerShell
# export MINI_PIPELINE_CONFIG=config/default.yaml # Linux/macOS

# 1. 启动后端 API（端口 8000）
.venv/Scripts/python -m uvicorn mini_pipeline.server.app:app --host 127.0.0.1 --port 8000
# 或使用注册的 CLI: mini-pipeline

# 2. 启动前端 Vite 开发服务器（端口 5173）
cd frontend
npm run dev
```

### 4.4 分布式 Runner Agent 启动
机器注册后可获得一次性机器令牌（`mrt_...`），在目标机运行：

```bash
# 手动启动
mini-pipeline-runner --server http://<SERVER_IP>:8000 --token mrt_xxxxxx --workspace ./runner-workspace

# 或使用一键跨平台安装指令：
# Windows (PowerShell):
powershell -c "irm http://<SERVER_IP>:8000/install?token=mrt_xxxxxx | iex"

# Linux / macOS (Bash):
curl -fsSL "http://<SERVER_IP>:8000/install?token=mrt_xxxxxx" | bash
```

### 4.5 数据库迁移与维护
```bash
# 生产环境执行数据库升级
alembic upgrade head

# 执行历史数据回收垃圾清理
mini-pipeline-gc --dry-run   # 预览
mini-pipeline-gc             # 执行
```

## 6. 关键模块说明

| 模块路径 | 职责定位 |
| :--- | :--- |
| `mini_pipeline.core` | 配置严格展开解析、单例依赖装配容器（`Services`）、进程内事件总线（`EventBus`）、日志格式化。 |
| `mini_pipeline.domain` | 定义系统统一契约：输入输出资源（`Resource`）、任务终态、领域异常（`AuthFailedError`, `NotFoundError` 等）。 |
| `mini_pipeline.database` | 抽象 SQLAlchemy ORM 模型与仓储层（`PipelineRepository`, `RunRepository`, `AccountRepository` 等）。 |
| `mini_pipeline.pipeline` | 解析 YAML 流水线定义，构建 DAG 依赖关系图，检测循环死锁，计算三类`${{ ... }}`动态取值表达式。 |
| `mini_pipeline.runtime` | 进程生命周期封装。`ProcessRunner` 统一处理标准流抽水、超时掐断、跨平台整树终止（`killpg`/`taskkill`）。 |
| `mini_pipeline.scheduler` | 推进 DAG 执行的调度中枢。基于 `coordinator_workers` 与 `task_workers` 分离并发，支持状态轮询与异步完成。 |
| `mini_pipeline.account` | 多用户账号注册登录、密码加盐哈希（`scrypt`）、Fernet 凭证加解密、机器资源管理与权限鉴别。 |
| `mini_pipeline.runner` | 分布式运行核心。包括拉取执行的 `agent.py`，以及基于 Paramiko 实现的推模式 `ssh_executor.py`。 |
| `mini_pipeline.server` | 装配根应用、监控探针（`/health`, `/metrics`）、SSE 实时推送流以及跨平台安装自适应路由（`/install`）。 |

## 7. 外部依赖

1. **操作系统工具**：
   - `git`：用于插件拉取及版本解析；
   - `bash`：运行 Shell 类型插件的解释器（Windows 优先定位 Git Bash）；
   - `python` / `python3`：执行 Python 类型插件及平台自身运行；
   - `taskkill`（Windows）/ `killpg`（POSIX）：用于超时或取消时干净彻底清理进程树。
2. **可选基础服务**：
   - **PostgreSQL 14+**：生产部署推荐数据库，支持并发行级锁 `SKIP LOCKED`；
   - **SSH 服务端**：用于 SSH 模式纳管的目标机器。
