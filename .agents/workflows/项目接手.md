# 项目接手

你现在是一个刚接手本项目的新 Agent。

你的目标不是立即修改代码，而是先恢复项目上下文，然后继续之前未完成的工作。

## 第一步：读取项目规则

首先阅读：

- AGENTS.md

必须遵守其中的项目规则。

不要修改 AGENTS.md。

## 第二步：读取项目状态

依次阅读：

- docs/agent/项目说明.md
- docs/agent/当前进度.md
- docs/agent/架构说明.md
- docs/agent/决策记录.md

如果某个文件不存在，不要自行创建替代内容，先说明缺失情况。

## 第三步：检查实际代码

不要完全相信项目文档。

根据当前进度中的“正在进行”“最近修改”“下一步”等信息：

1. 定位相关代码。
2. 检查当前实现。
3. 检查 Git 状态。
4. 检查最近的代码修改。
5. 检查相关测试。

确认文档描述和实际代码是否一致。

## 第四步：恢复当前工作状态

整理出：

### 项目是什么

用简短的中文说明项目目的。

### 当前阶段

说明当前项目处于什么阶段。

### 已完成

只列出已经从代码或测试中确认完成的内容。

### 正在进行

说明之前 Agent 正在做什么。

### 未完成

说明还有哪些工作没有完成。

### 当前问题

列出：

- Bug
- 测试失败
- 配置问题
- 技术问题
- 阻塞问题

### 最近修改

列出之前 Agent 最近修改的重要文件以及修改目的。

### 重要技术决策

列出当前不能随意推翻的设计。

## 第五步：确定接下来应该做什么

根据实际代码和项目状态，确定最合理的下一步。

不要重新设计整个项目。

不要重复已经完成的工作。

优先继续之前 Agent 没完成的工作。

## 第六步：向用户汇报

先不要修改代码。

用下面格式告诉用户：

# 项目接手完成

## 项目

xxx

## 当前阶段

xxx

## 上一个 Agent 已完成

- xxx
- xxx

## 上一个 Agent 未完成

- xxx
- xxx

## 当前发现的问题

- xxx

## 我确认过的代码

- xxx
- xxx

## 下一步

1. xxx
2. xxx
3. xxx

最后询问用户：

“如果没有其他要求，我将从上述下一步开始继续工作。”
