# 项目交接

请为下一个 Agent 准备项目交接信息。

## 1. 阅读项目状态

阅读：

- docs/agent/项目说明.md
- docs/agent/当前进度.md
- docs/agent/架构说明.md
- docs/agent/决策记录.md

## 2. 检查实际代码

根据当前进度中的描述，检查关键内容是否与实际代码一致。

如果发现不一致：

先指出不一致，不要直接假设文档正确。

## 3. 生成交接摘要

使用以下结构：

### 项目是什么

用几句话说明项目目的。

### 当前阶段

说明当前处于哪个阶段。

### 已完成

列出已经确认完成的主要功能。

### 正在进行

列出当前正在实现的功能。

### 未完成

列出后续主要工作。

### 当前问题

列出：

- Bug
- 测试失败
- 配置问题
- 技术债务
- 阻塞问题

### 重要文件

列出下一个 Agent 最应该阅读的文件。

### 重要架构

简要说明当前架构和模块关系。

### 重要决策

列出不能随意推翻的技术决策。

### 下一步

给出明确的下一步操作。

不要给出模糊的：

“继续完善项目”

而应该给出类似：

“先修改 A 文件中的 B 函数，然后运行 C 测试，确认通过后再实现 D。”

## 4. 不修改源代码

这个工作流只负责项目理解和交接。

除非发现项目文档明显过期，否则不要修改业务代码。
