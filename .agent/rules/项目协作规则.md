# 项目协作规则

## 语言要求

所有项目文档使用中文。

代码、变量名、函数名、类名等遵循项目原有命名规范，不强制翻译。

---

## 项目状态文件

项目的长期状态统一保存在：

- `docs/agent/项目说明.md`
- `docs/agent/当前进度.md`
- `docs/agent/架构说明.md`
- `docs/agent/决策记录.md`

这些文件是不同 Agent 之间进行项目交接的主要依据。

---

## 开始任务前

开始任何中等以上规模的任务之前：

1. 阅读 `docs/agent/项目说明.md`
2. 阅读 `docs/agent/当前进度.md`
3. 根据任务需要阅读 `docs/agent/架构说明.md`
4. 根据任务需要阅读 `docs/agent/决策记录.md`
5. 检查实际代码，不允许只相信文档。

如果文档和实际代码不一致：

- 以实际代码为准
- 修正文档
- 在当前进度中说明发现了不一致

---

## 工作过程中

执行任务时持续关注：

- 已完成什么
- 正在做什么
- 还有什么没有完成
- 修改了哪些文件
- 运行了哪些测试
- 测试是否通过
- 是否产生新的问题
- 是否产生重要技术决策

---

## 禁止事项

禁止：

1. 把没有验证的内容写成已经完成。
2. 把推测写成事实。
3. 为了让进度看起来更高而虚报完成度。
4. 随意删除项目已有功能。
5. 没有必要时进行大规模重构。
6. 修改架构后不更新架构说明。
7. 做出重要技术决策后不记录决策原因。

---

## 完成任务后

任务完成之前必须更新：

`docs/agent/当前进度.md`

至少记录：

- 本次完成内容
- 修改文件
- 测试情况
- 当前遗留问题
- 下一步工作

如果产生重要架构决策：

同时更新：

`docs/agent/决策记录.md`

如果架构发生变化：

同时更新：

`docs/agent/架构说明.md`

---

## 关于完成状态

只有在实际代码已经完成并经过验证后，才能标记：

`已完成`

如果只是部分实现：

标记：

`进行中`

如果还没有开始：

标记：

`未开始`

如果无法确定：

标记：

`需要确认`

---

## Agent 交接要求

每次结束工作时，都必须让另一个完全不了解本项目的 Agent 能够仅通过项目文档快速理解：

1. 项目是什么
2. 当前做到哪里
3. 最近做了什么
4. 当前正在做什么
5. 有什么问题
6. 下一步应该做什么
7. 哪些地方需要特别注意

---

## 重要

项目文档是持久化状态，不是聊天记录。

不要把大量无意义的过程日志写入项目文档。

只记录对后续 Agent 有价值的信息。
